# 虚拟文件系统（VFS）

## 作业目标

* 学会使用 STL 库
* 加深对于字符串处理的掌握
* 提高模拟水平，掌握基本的拆分功能、规划项目的能力
* 学会设计类型系统与类型检查规则
* 学会使用迭代器

## 作业要求

本作业要求实现一个**虚拟文件系统（VFS）**，模拟目录树、名字解析、文件类型系统，以及删除、统计等文件操作。

在该文件系统中，目录（directory）可以包含子目录和文件，文件（file）保存具体的内容。不同的目录下可以存在同名文件，互不干扰。

当我们在某个目录中使用一个**名字**（例如 `x.txt`）时，只在**当前目录的直接子项**中查找，不向父目录逐级搜索。例如：

```
/           — 根目录
/x.txt      — 内容 "root"
/a/         — 子目录
/a/x.txt    — 内容 "inner"
/a/b/       — 子目录
```

当当前目录是 `/a` 时，`x.txt` 解析为 `/a/x.txt`；当当前目录是 `/` 时，解析为 `/x.txt`。当当前目录是 `/a/b` 时，`cat x.txt` 输出 `Invalid operation`，不会访问父目录中的同名文件。本文件系统没有名字遮蔽规则；要访问其他目录中的文件，必须先切换到该目录。

### 重要概念解释

* **根目录** `/` 是文件系统的顶层目录，程序开始时的当前目录（`cwd`）就是根目录。
* 每个目录包含若干子目录与文件，**同一目录下不允许重名**（文件与目录共用名字空间）。
* **直接子项**：直接属于当前目录的文件或子目录，不包括子目录的后代与父目录中的项。所有带名字参数的操作都只查找当前目录的直接子项；`cd` 接受路径参数，按路径逐段解析。
* `mkdir` / `create` 在当前目录创建直接子项；`rm` / `rm -r` 只作用于当前目录的直接子项；`cd` 支持绝对路径与相对路径，`cd ..` 返回父目录。
* `cat` / `stat` / `append` / `read` / `write` 同样只查当前目录的直接子项。目标不存在或类型不满足操作要求时，输出 `Invalid operation`，不继续向父目录查找。
* `rm -r` 找到当前目录的直接子目录后，递归删除它的整棵子树。

例如：当前目录 `/a` 下没有 `x.txt` 但根目录下有 `x.txt` 时，`cat x.txt` 与 `rm x.txt` 都输出 `Invalid operation`；返回根目录后，才能操作根目录的 `x.txt`。

`top` / `ls` / `undo` / `redo` / `tree` 不接受名字参数，不涉及名字解析；其中 `top` 只统计当前目录的直接子文件。

## 指令总览

**必做指令**

| 指令 | 说明 |
| --- | --- |
| `mkdir [name]` | 在当前目录创建子目录 |
| `cd [path]` | 按绝对路径或相对路径切换目录 |
| `create [type] [name] [content]` | 在当前目录创建文件 |
| `append [name] [content]` | 向文本文件追加内容 |
| `cat [name]` | 输出文本文件内容 |
| `ls` | 列出当前目录 |

| `read [name] [offset] [length]` | 读取 bin 文件的字节区间 |
| `write [name] [offset] [hexdata]` | 向 bin 文件写入字节 |
| `top [k]` | 当前目录内大小最大的 k 个文件 |
| `stat [name]` | 输出指定名字（文件或目录）的类型与大小 |

## 指令介绍

### `mkdir [name]`

在当前目录下创建一个子目录。

```
mkdir src
```

要求：

* 当前目录下已有同名项（文件或目录）时：`Invalid operation`。

### `cd [path]`

* `[path]` 以 `/` 开头时为**绝对路径**，从根目录开始解析；否则为**相对路径**，从当前目录开始解析。
* 路径以 `/` 分隔，`.` 表示所在目录，`..` 表示父目录，普通名字表示该目录的直接子目录。
* `cd /`：返回根目录；`cd ..`：返回父目录；`cd .`：留在当前目录。

```
cd src
cd ..
cd /a/b
cd ../b
cd ./b
cd /
```

要求：

* 路径格式保证正确（见"名字与字符串规则"），不出现连续 `/`；除根路径 `/` 外，不以 `/` 结尾。
* 从左到右逐段解析，每个普通名字都必须对应已存在的直接子目录。目标不存在或是文件时：`Invalid operation`。
* 任一步失败时，整条指令失败，当前目录保持执行前的状态，不产生可撤销记录，也不清空的可重做记录。
* 成功时切换到最终目录，整条 `cd` 只产生一条可撤销记录；即使最终目录未改变，成功执行仍记录。

### `create [type] [name] [content]`

在当前目录下创建一个类型为 `[type]`、名为 `[name]` 的文件，内容为 `[content]`。

```
create txt main.cpp "int main()"
create md README.md "# title"
create bin data.bin "48 65 6C 6C 6F"
```

要求：

* 当前目录下已有同名项：`Invalid operation`（同名文件只允许出现在不同目录中）。
* `[content]` 是以 `"` 开头并以 `"` 结尾的字符串常量（见"名字与字符串规则"）。
* 三种类型都允许空内容：`create txt a.txt ""` 创建空文本文件。
* `[type]` 为 `bin` 时，`[content]` 为大写十六进制字节序列，需要解析为字节保存；空串 `""` 表示空文件（规则见"名字与字符串规则"）。

`txt` 与 `md` 是**文本文件**；`bin` 是**二进制文件**。三种文件的内部格式不同，但输入内容均为字符串字面量。

### 文件格式

三种文件类型具有不同的内部格式：

* **`txt`（纯文本文件）**：内容以字符序列形式保存，是最基本的文本文件。
* **`md`（文档文件）**：内容同样是字符序列，但作为一种独立的文档类型存在，与 `txt` 是两种不同的类型。
* **`bin`（二进制文件）**：内容以**字节序列**形式保存，与文本文件的保存方式不同。创建时传入的 `[content]` 为大写十六进制字节序列；创建后可用 `read` / `write` 按字节操作。

相关规则：

* 文本操作（`append` / `cat`）只接受文本文件（`txt` / `md`）；`bin` 参与时输出 `Invalid operation`。
* 三者 `size` 统一按内容字节数计算（`txt` / `md` 为字符串长度，`bin` 为字节序列长度）；目录固定为 `0`。
* 三种类型的区别通过 `stat` 输出的类型名体现。

### `append [name] [content]`

向文本文件追加内容。

```
create txt a.txt "hello"
append a.txt "world" // a的内容为"helloworld"
```

要求：

* `[name]` 必须是当前目录的**直接子项**，否则 `Invalid operation`。
* `[name]` 必须是文本文件（`txt` / `md`）。是目录或 `bin` 时：`Invalid operation`。
* 允许追加空串；成功执行仍产生一条可撤销记录。

### `cat [name]`

输出文件的名字与内容。

```
cat a.txt
```

输出格式：`[name]:[content]`，例如 `a.txt:hello`。空文件输出 `[name]:`（冒号后无内容），与 `read` 的 `[length] = 0` 情形一致。

要求：

* `[name]` 必须是当前目录的**直接子项**，否则 `Invalid operation`。
* `[name]` 必须是文本文件（`txt` / `md`）。是目录或 `bin` 时：`Invalid operation`。

### `read [name] [offset] [length]`

读取 bin 文件从字节位置 `[offset]` 起的 `[length]` 个字节并输出。

```
read a.bin 10 20
```

输出格式：`[name]:[hex]`，`hex` 为大写、单空格分隔的十六进制字节组，例如 `a.bin:01 02 03`。`[length]` 为 0 时输出 `[name]:`（冒号后无内容）。

要求：

* `[name]` 必须是当前目录的**直接子项**，且必须是 `bin` 文件。不存在、是目录或文本文件时：`Invalid operation`。
* `[offset] + [length]` 不得超过文件大小，否则 `Invalid operation`。
* `read` 不改变文件系统状态，不产生可撤销记录。

### `write [name] [offset] [hexdata]`

将 `[hexdata]` 表示的字节序列从字节位置 `[offset]` 起**覆盖**写入 bin 文件，不移动后续字节。例如原内容 `01 02 03 04`，执行

```
write a.bin 1 "FF FF"
```
后为 `01 FF FF 04`。

要求：

* `[name]` 必须是当前目录的**直接子项**，且必须是 `bin` 文件。不存在、是目录或文本文件时：`Invalid operation`。
* `[hexdata]` 为非空的大写十六进制字节序列，以 `"` 开头并以 `"` 结尾的字符串常量形式给出（规则见"名字与字符串规则"）。
* `[offset] + [hexdata] 字节数` 可以超过文件末尾：超出部分**扩展文件**。`[offset]` 大于原文件大小时，原末尾到 `[offset]` 之间的空缺字节补 `0`。
* 成功的 `write` 产生可撤销记录，即使写入字节与原字节相同。

### `ls`

列出当前目录下的所有直接子项，按名字字典序每行一个，目录项带 `/` 后缀。若当前目录为空则无输出。

例如当前目录包含 `b.txt`、`a.txt` 与目录 `src`，输出：

```
a.txt
b.txt
src/
```

按字典序：`a.txt` < `b.txt` < `src`，**注意目录按不含 `/` 的名字参与排序。**

### `rm [name]`

删除当前目录下的一个直接子文件。

```
rm a.txt
```

例如：

```
create txt note.txt "hi"
rm note.txt
```

要求：

* `[name]` 必须是当前目录的**直接子项**（只查当前目录），否则 `Invalid operation`。
* `[name]` 是文件时直接删除；是目录（无论是否为空）时输出 `Invalid operation`。`rm` **只能删除文件，不可以删除目录**。
* 成功的 `rm` 产生可撤销记录；被删除的文件可被 `undo` 完整恢复。

### `top [k]`

输出当前目录内大小最大的 `k` 个文件。

```
top 3
```

输出格式：每行 `[name]:[size]`，按 `size` 降序排列；`size` 相同时按名字字典序排列。`size` 为内容字节数（`txt` / `md` 为字符串长度，`bin` 为字节序列长度）。

要求：

* 只统计当前目录的**直接子文件**（不含子目录、其他目录内文件）。
* `k` 保证为正整数；`k` 大于文件总数时全部输出；没有文件时无输出。

### `stat [name]`

输出指定名字（文件或目录）的类型与大小。

```
stat a.txt
```

输出格式：`[name]:[type]:[size]`。`type` 为 `txt` / `md` / `bin` / `dir` 之一；`size` 为内容**字节数**，目录的 `size` 固定为 `0`。

要求：

* `[name]` 必须是当前目录的**直接子项**，否则 `Invalid operation`。

### `undo` / `redo`（`redo` 为 Bonus）

`undo` 撤销最近一次成功执行的可撤销操作，使文件系统恢复到执行该操作之前的状态；`redo` 重做最近一次被 `undo` 撤销的操作。主体只要求实现 `undo`，`redo` 为 Bonus 指令。

```
undo
redo
```

要求：

* 可撤销操作包括 `mkdir` / `create` / `append` / `cd` / `write` / `rm`；若实现了 `rm -r`（Bonus），同样需要支持撤销。
* 只有成功执行的可撤销操作会产生记录。即使内容未变化（如 `append` 空串、`write` 写入相同字节），成功执行仍产生一条记录；查询操作与输出 `Invalid operation` 的操作不产生记录。
* `undo` 与 `redo` 均按后进先出顺序处理记录，两条指令本身不额外产生操作记录，均可连续执行。
* Bonus 中，成功的 `undo` 将最近一条可撤销记录移入可重做记录；成功的 `redo` 将最近一条可重做记录移回可撤销记录。
* Bonus 中，任何成功执行的可撤销操作都会清空可重做记录；查询操作与输出 `Invalid operation` 的操作不清空。
* 没有可撤销记录时 `undo` 输出 `Invalid operation`；Bonus 中，没有可重做记录时 `redo` 输出 `Invalid operation`。

## 名字与字符串规则

本节定义输入的格式规则。**输入保证格式正确**，程序中不需要检查格式错误，但解析需要按这些规则进行。

* **名字（name）**：非空，不含 `/`，不含空白字符（空格、制表符等），不含 `"`，不是 `.` 或 `..`，长度不超过 20 个字节（按字节计）。除 `.` 与 `..` 外，以 `.` 开头的名字（如 `.gitignore`）是合法且普通的名字。
* **路径（path，仅用于 `cd`）**：非空，不含空白字符或 `"`；可为根路径 `/`，也可由可选的开头 `/` 和若干以单个 `/` 分隔的非空路径段组成。路径段为 `.`、`..` 或符合名字规则的普通名字。保证没有连续 `/`，除根路径 `/` 外没有末尾 `/`；20 字节限制只针对每个普通名字，不针对整个路径。
* **无隐藏文件规则**：本文件系统不区分隐藏文件，名字是否以 `.` 开头不产生任何特殊语义，`ls` 与 `tree` 一律输出所有子项。
* **字符串常量（content）**：以 `"` 开头并以 `"` 结尾，中间为任意内容（可含空格），不支持转义字符，中间不能出现 `"`。解析时取第一个 `"` 与最后一个 `"` 之间的内容。
* **十六进制字节序列（`bin` 的 content）**：由单个空格分隔的若干**两位十六进制数字**组成，仅含 `0-9`、`A-F`；不含小写字母与多余空格。`create` 允许空串（空文件）；`write` 的序列非空。
* **大小（size）**：文件为内容字节数；目录为 `0`。

## 输入格式

第一行一个整数 `n`，表示指令条数。之后共 `n` 行，每行一条指令。

保证：

* 指令的关键字必然合法（每行第一个单词必为上述指令之一），每行参数数量正确。
* 名字、`cd` 的路径、字符串常量、十六进制字节序列均符合"名字与字符串规则"；`[type]` 必为 `txt` / `md` / `bin` 之一。
* `top` 的 `k` 为正整数；`read` / `write` 的数字参数为非负整数。

**输入格式保证正确**指每行都符合对应指令的参数写法与取值规则：指令条数、参数个数、名字、路径、引号、类型、数字范围，以及 `create bin` 的 `[content]` 和 `write` 的 `[hexdata]` 都满足上述格式要求。即使目标文件不存在、已重名或类型不对，也不会出现格式错误的参数；程序不需要处理格式错误，格式错误的输入没有规定输出。

**不保证语义正确**指格式正确的指令执行时仍可能因文件系统的当前状态或操作要求而失败：重复创建同名项、名字不存在或不是当前目录的直接子项、对不符合操作要求的文件类型执行操作（如对 `bin` 文件执行 `cat`、对文本文件执行 `read`）、读取越界、`cd` 路径中的目录不存在、遇到文件或尝试越过根目录、对目录执行 `rm`、`undo` / `redo` 无记录等。这类错误按对应指令规则输出 `Invalid operation`，并继续处理后续指令。

例如 `create bin dd "41"` 是格式正确的创建指令；若随后执行 `cat dd`，由于 `cat` 只接受文本文件，属于语义上的类型不匹配，应输出 `Invalid operation`。而 `create bin dd "same"` 的内容不是十六进制字节序列，属于**输入格式错误**，不会作为测试输入；`create txt dd "same"` 中的普通文本内容则是合法的。

数据范围：`n <= 2e5`，目录嵌套深度小于 100，数字参数（`read` / `write` 的 `offset`、`length`，`top` 的 `k`）不超过 1e6。

## 输出格式

* `cat`：输出 `[name]:[content]`。
* `read`：输出 `[name]:[hex]`，`hex` 为大写、单空格分隔的十六进制字节组。
* `stat`：输出 `[name]:[type]:[size]`。
* `top`：输出 `[name]:[size]`，`size` 降序、同 `size` 按名字字典序。
* `ls`：名字字典序，目录带 `/`。
* 任何语义上非法的操作：输出 `Invalid operation` 并换行。非法操作不影响程序继续执行。

输入：

## Tips

* 数据量达到 `2e5`，建议在 `main` 开头加上：

```cpp
std::ios::sync_with_stdio(false);
std::cin.tie(nullptr);
```

* 输入规模较大，注意避免不必要的线性查找。
* 建议使用合适的STL容器设计目录树结构，并考虑名字解析效率。目录子项可以使用 `map` 或 `unordered_map`；名字操作限定为直接子项，`cd` 则需要逐段解析路径。可以保存父节点关系或路径信息，处理路径中的 `..`。
* `top` 可以维护按大小和名字排序的增量索引。
* 可能用到的头文件的一部分：

```
<map>
<unordered_map>
<set>
<vector>
<stack>
<queue>
<deque>
<utility>
<optional>
<tuple>
<variant>
<algorithm>
```

## Bonus 说明

* `redo`：重做最近一次被 `undo` 撤销的操作，具体规则见"`undo` / `redo`"。
* `rm -r [name]`：删除当前目录下的**直接子项**。文件直接删除；目录**递归删除**（连同其整棵子树）。只查当前目录直接子项，否则 `Invalid operation`。成功的操作产生可撤销记录，`undo` / `redo` 可以恢复或再次删除被删除的文件或整棵子树。
* `tree`：从当前目录开始，以缩进树形式输出整棵子树，不改变文件系统状态。
  - 首行为当前目录名（路径最后一段）加 `/`（根目录为 `/`），空目录也输出首行。
  - 每行一个节点；同一目录下按名字字典序排列（目录按不含 `/` 的名字参与排序，与 `ls` 一致），目录带 `/`。
  - 本文件系统**没有隐藏文件规则**：以 `.` 开头的名字与普通名字完全等价，`ls` 与 `tree` 都一律输出，不做任何过滤。
  - 缩进使用 UTF-8 制图字符：非最后一项前缀 `├── `，最后一项前缀 `└── `；进入子目录后，其子项前缀分别延续 `│   ` 与 `    `（四个空格）。
  - 输出文件须为 UTF-8 编码。

完整示例（执行到 `tree` 时当前目录为 `/a`）：

输入：

```
11
mkdir a
cd a
create txt f "x"
mkdir b
cd b
create txt g "y"
cd ..
rm -r b
undo
redo
tree
```

输出：

```
a/
└── f
```
